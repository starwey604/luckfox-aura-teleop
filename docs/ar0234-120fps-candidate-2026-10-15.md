# AR0234 双路约120fps：候选内核与测试准备

2026-10-15。**时序计算支持约119.95fps，#19候选镜像已完成编译，尚需用户刷写和实机验证。**
当前板端仍为#18，只实际补测了约99fps基线；不能把下面的候选值写成双路已达120fps。

## 时序与限制

保持四通道RAW10、24MHz输入、900Mbps/lane、内部90MHz读出、612行长、1280×720和6.8µs行时间：

| 参数 | 原默认/已验证 | 约120fps候选 |
|---|---:|---:|
| VBLANK | 762 | 506 |
| FRAME_LENGTH_LINES寄存器 | 1477 | 1221 |
| 总行数，含5行开销 | 1482 | 1226 |
| 帧周期 | 10.0776ms | 8.3368ms |
| 对应fps | 99.22998 | 119.95010 |
| 垂直空白预算 | 5.1816ms | 3.4408ms |
| 720行有效输出预算 | 4.896ms | 4.896ms |
| exposure735 | 4.998ms | 4.998ms |

1226为`ceil(1/(120×6.8µs))`，离散行数使它略低于精确120；没有声称精确120.000fps。
候选空白仍超过CIF在线ISP路径提示的1ms，曝光也低于新帧长允许的上限1220行。
固定曝光/增益，不需要为了提高fps再增加内部clock或修改lane速率。
输出帧数和平均ISP/编码处理量约增加21%；是否双路持续承受，需要实测。
同一码率下每帧可分配码字减少，首轮保持30Mbps/路，以便分离时序变化。

缩短帧周期可能减少等待下一次采样的相位时间，但不会把约4.9ms读出变成更短。
不能直接承诺screen-to-screen减少1.74ms；若相位均匀，单看等待采样的均值改善约0.87ms，仅作预算。

## 软件修改

kernel commit `c3fde23bf`，保存为kernel第22条patch：

- 将`ar0234_min_vblank`与default分开：fastreadout配置的min为506，default仍为762，
  原两通道/参考配置的最小值保持原样。开机和默认初始化仍为约99.23fps。
- init_controls、枚举最快帧间隔、真正换模式、S_FRAME_INTERVAL的clamp使用同一最小值。
- 相同sensor模式的重复S_FMT保留已经设置的帧间隔；真正换模式仍重设对应控件范围和默认时序。
  否则启动VI时有可能把用户设置的506重新改回762，造成“写了120，实际仍99”。
- 未修改商家PLL/初始化表、默认曝光、设备树接线、内核CONFIG或电源/网络策略。

测试工具新增VBLANK/encoder-fps和可选stage-metrics参数。VENC的`--fps`只声明率控参数，
sensor必须通过VBLANK真正改速；脚本读回VBLANK并采集CIF帧周期，再看sender/host AU间隔。
`--minimal --stage-metrics`启用本地stage计时，但不启用重型板端监控或生命周期逐调用打印。
默认参数和关闭metrics的旧行为保持不变。

## 需要用户刷写后继续

完整镜像已独立保存在ignored `artifacts/ar0234-120fps-20261015/image/`。
现用sender/两个辅助脚本在旁边`runtime/`备份。SDK当前output/image也是这套#19，
但运行中的板子并不会因为本机构建完成自动更换内核。

用户将板子置于Loader后，在项目目录手动全量烧录：

```sh
./tools/flash-aura-emmc --images artifacts/ar0234-120fps-20261015/image
```

全量会覆盖userdata。刷好后先核对#19、USB、公钥和SSH，再从runtime恢复同一个sender及辅助脚本；
不要在还没恢复文件时假定`/userdata/teleop-sender`存在。本轮没有代用户烧录或重启。

后续先单目camera0/1各120帧，再单进程双路各120帧；温度与USB日志要求沿用现有短测政策。
例如原生CachyOS上用于双路B的命令（新输出目录）：

```sh
./tools/test-ar0234-readout --camera dual --frames 120 --expect-lanes 4 \
  --exposure-us 4998 --analogue-gain 48 --digital-gain 512 \
  --vertical-blanking 506 --fps 120 --stage-metrics \
  --output artifacts/ar0234-120fps-20261015/B120-new
```

验收看实际：CIF周期约8.337ms，sender/host的AU间隔也约8.337ms、无持续队列增长，
解码计数完整，无CSI/内核错误；不能只依据命令行、H.264声明fps或sensor报告值判为通过。
采样快照不覆盖每一帧，短测通过也不等于长时间稳定性验证。

如B通过，手动正常启动时板端需要同时设置sensor空白和编码器声明：

```sh
VERTICAL_BLANKING=506 FPS=120 EXPOSURE=735 ANALOGUE_GAIN=48 DIGITAL_GAIN=512 \
  /userdata/run-ar0234-stereo
```

不设置VBLANK时仍为原约99.23fps。若需要返回原时序，显式`VERTICAL_BLANKING=762 FPS=100`；
单独删除环境变量不会复位已经缓存的sensor控件。测试脚本会主动恢复测试前的控件。
