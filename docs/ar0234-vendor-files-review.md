# DECXIN-3478V1 商家文件核对（2026-10-12）

后续已完成商家 720p 两通道配置移植，见 [720p 接入记录](ar0234-720p-bringup.md)。
随后核对 Aura 官方原理图，确认 Aura 与模组的同号引脚表匹配，见
[接线核对记录](ar0234-wiring-confirmation.md)。
下面保留资料核对时的差异与结论。

## 结论

文件足以建立商家版本的两通道 RAW10 初始化基线，但还不足以确认完整电气接线。
PDF 是单页结构/接口图，不是 AR0234 寄存器规格书或模组原理图。
INI 提供 1080p 60fps 和 720p 99.2fps 两个模式，没有四通道 120fps 模式。
本轮仅核对并记录，没有修改 SDK 驱动、设备树或烧录镜像。

移植时以数值为准，再通过芯片资料核对含义。

## 图纸确认的接口

连接器是 22P、0.5mm、翻盖下接触；模组约 32×32mm，侧视总高度 22.1±0.2mm。
镜头视角标注 D=123°、H=112°、V=82.6°；阵列为 1920×1200。

| 图纸 pin | 信号 |
|---|---|
| 1 | 3.3V |
| 2 / 3 | SDA / SCL |
| 4、7、10、13、16、19、22 | GND |
| 5 / 6 | NC / NC |
| 8 / 9 | MDP3 / MDN3 |
| 11 / 12 | MDP2 / MDN2 |
| 14 / 15 | MCP / MCN |
| 17 / 18 | MDP1 / MDN1 |
| 20 / 21 | MDP0 / MDN0 |

四对数据线已引出，实际 lane 数由初始化与接收端配置决定。
该表的排列与常见树莓派 22-pin 定义在编号反向后对应，但这不能代替排线
两端触点及 pin 1 的实物核对。

另有 STRB、TRG、GND 三针接口，图纸标注 1.25 立式插件。
引脚存在不代表已有触发配置，图纸没有给出触发电平、极性、脉宽或工作模式。

图纸区分了连接器输入 3.3V 和芯片电源 AVDD=2.8V、DOVDD=1.8V、DVDD=1.2V。
后面三项不能直接当作主板连接器供电要求；是否由模组内部生成要看电路。
22-pin 没有明确标注 MCLK/reset/PWDN，5/6 为 NC。
因此不能照抄 MIA1321 的 reset GPIO，也不能仅凭 `XMCLK=24MHz` 认定
需要从 Aura 输出 24MHz；板载晶振与电源控制电路仍待商家确认。

## INI 的两个模式

两套均 `XMCLK=24000000`、`0x31AE=0x0202`、`0x31AC=0x0A0A`：
24MHz 输入时钟、两通道 MIPI、RAW10。PLL 写入值与当前移植的 RAW10 表一致。
两套模式共有寄存器的最终值只在七个地址不同：裁剪范围、行长、帧长和曝光。

| 参数 | 1080P 60fps | 720P 99.2fps |
|---|---:|---:|
| 输出区域（由起止寄存器计算） | 1920×1080 | 1280×720 |
| `0x3004/0x3002`：X/Y start | 8 / 68 | 328 / 248 |
| `0x3008/0x3006`：X/Y end | 1927 / 1147 | 1607 / 967 |
| `0x300C`：行长 | 681 (`0x02A9`) | 612 (`0x0264`) |
| `0x300A`：帧长寄存器 | 1096 (`0x0448`) | 736 (`0x02E0`) |
| `0x3012`：曝光行数 | 462 (`0x01CE`) | 514 (`0x0202`) |
| 按参考时序模型计算 fps | 60.0175 | 99.2300 |
| 按参考时序模型计算曝光 | 6.9916ms | 6.9904ms |

计算采用文件名的 45MHz 读出 clock 和现有参考模型的五行帧开销：
`fps = 45,000,000 / (line_length * (frame_length_register + 5))`。
两个结果与文件标称吻合，支持该时序模型；仍需用采集时间戳确认。
如果省略五行开销，结果分别是 60.2913 / 99.9041fps。
720p 是裁剪输出，不能当作保持完整视场的缩放模式。

## 与当前 SDK 驱动的差异

| 项目 | 当前参考移植 | 商家 INI / 需要处理 |
|---|---|---|
| 1080p 行长 | 612 | 681，需要按模式保存行长、HBLANK 和帧率 |
| 1080p 默认帧长 | 1096 | 1096；因行长不同，当前模式约 66.78fps，商家约 60.02fps |
| MIPI timing 4 `0x31BC` | `0x0D89`，要求非连续时钟 | `0x8D89`，连续时钟候选配置，需同步接收端 |
| 模拟参数 `0x3ED2` | `0xFA96` | `0xFA86` |
| 2-lane seq / gain setting | 启动中写 `0x81BA/0x3D02`、`0x30BA=0x7626` | 商家也是这些值，比较时要考虑整个写入顺序 |
| 镜头阴影校正 | 未提供 | 商家提供 POLY 系数并最终写 `0x3780=0x8000` |
| 默认曝光 | 100 行 | 约 7ms；低延迟测试建议出图后缩短并补光 |
| metadata `0x3064` | 明确写 `0x1802` | 未写，需核对复位默认值与 RAW 图像边界 |
| 温度传感器 `0x30B4` | 写 `0x0011` | INI 未写，需决定是否保留 |
| 启动步骤 | 软件复位后初始化，最后启动 | 商家额外启停、200/50/50 延时，延时单位需确认 |

对连续时钟的判断来自 `0x31BC` 仅差 bit 15，以及
[Linux-media 作者提交的驱动](https://www.spinics.net/lists/linux-media/msg273780.html)
对该寄存器连续/非连续配置的标注，属于待规格书/实机确认的推断。
INI 的镜头阴影校正属于 sensor 端参数，不等于 Rockchip ISP IQ 文件。

## 下一轮建议

1. 为这款模组增加单独的商家 profile，保留已移植的通用参考模式，避免混合两种
   来源的初始化。商家 profile 优先限定 RAW10、2-lane，先验证 1080p60 或 720p99.2。
2. 让行长、帧长默认值与 MIPI clock mode 随 profile/mode 变化；完整处理公共表、
   POLY 校正、重复写入、启动延时和控件覆盖顺序。
3. 核对 I²C 7-bit 地址、板载 24MHz 晶振/主板 MCLK、3.3V 供电与电平转换、
   reset/PWDN 是否内部处理、排线两端 pin 映射。
4. 补齐 DTS 并编译，镜像由用户烧录；先验证 RAW 测试图案和实际帧率，
   再验证 ISP NV12 / MPP。720p 默认曝光近 7ms，出图后再做短曝光延迟测试。
5. 四通道 120fps 等两通道出图后验证；向商家索取该模式的寄存器表、最高 lane
   速率，以及 TRG/STRB 的时序和电平规格，不能只改 `0x31AE` 就认定可达 120fps。
