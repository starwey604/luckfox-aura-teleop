# K1 内核裁剪候选与 A/B 记录

2026-10-13。本轮已完成 **A 的实机基线、B 的内核/模块编译与镜像打包**。
B 尚未烧录，尚无裁剪前后性能结论。没有自动烧录、重启或改动摄像头时序。

## 本轮变量

A 为板端当前 `6.1.141 #16 SMP PREEMPT` 诊断内核，包含已通过回归的 KMPP IRQ 修复。
双方使用上一轮优化后的同一 sender/viewer，SDK mode1 完整 AU 立即发送、完整 AU 直接硬解。
每路 1280×720、约 99 fps、30 Mbps、GOP15、slice120、双路 wrap0，保持原 AR0234 采集时序。

B 新增 `ar0234-stereo-k1` BoardConfig，在 **相同的 lifecycle debug fragment 后**叠加
`rv1126b_teleop_k1.config`：关闭 SOUND、NETFILTER、BRIDGE、TUN、VETH、USB_VIDEO_CLASS，
以及当前启用的非 AR0234 sensor（包括 MIA1321、IMX415/586、GC/SC/OS/PS 和 Techpoint）。
后续再分别推进无线、显示/NPU、Buildroot 和最终 USB 裁剪；本轮没有一次性合并所有阶段。
无线需要配套调整独立模块构建、模块加载和用户空间服务，留待独立一组处理。

保留 USB host/gadget、ADB、显示/NPU、无线、IPv6、SSH、千兆网、eMMC/ext4、I²C/UART、
thermal/watchdog、CMA256M、CIF/ISP/VPSS/AIISP/RGA/DVBM、DMA heaps 和所有 MPP/Rockit 核心模块。
保留 PREEMPT、HZ1000、O2、无 LTO、相同 IRQ 分配与 governor；这些不是本轮新增优化。
没有修改 DTS、sensor 寄存器、VBLANK、曝光时序、网络 sysctl、NIC 合并参数或程序二进制。

SDK 原有 `S35iptables` 和声卡初始化命令仍在根文件系统中，关闭对应驱动后可能打印“不支持”错误。
这版是隔离内核变量的开发镜像，尚非最终干净的启动服务精简版；刷写后需要检查这些失败不会阻断 SSH/视频初始化。

## 编译、打包与可重放性

在 Ubuntu22.04 Distrobox `aura-sdk` 执行 `./build.sh driver` 和 `./build.sh firmware`，
保留 GCC12.4/O2，并让 Kbuild/SDK 重新处理内核及外置模块。所有模块 vermagic 匹配
`6.1.141 SMP preempt mod_unload aarch64`；仍需上板验证初始化，vermagic 不是完整 ABI 兼容性证明。

| 检查 | A | B |
|---|---:|---:|
| 有效 y/m 符号数 | 1297 | 1177 |
| boot.img 字节数 | 11,390,976 | 10,434,048 |
| boot 固定分区容量 | 11,534,336 | 11,534,336 |
| Buildroot 配置 | 原 teleop 配置 | 不变 |

boot 缩小 956,928 字节，约 0.91 MiB。配置有 534 个文本层面的符号差异，
其中包含依赖消失的 n 符号；不能将它说成“删除 534 个驱动”。有效启用数减少 120。

直接从保存的 A/B ext4 镜像中导出并比较，Rockit、MPP、libdrm、libasound、glibc、
dhcpcd.conf、sshd_config、S02teleop-performance 的 SHA256 完全相同。
Buildroot config SHA256 也和 10月12日审计一致。MPP `kmpp.ko` 编译后的 SHA256 仍为
`b75dda4ef396acac8ca8eacdef2203c2bb540fd783a564cc2577788079c618aa`。
内核配置裁剪不涉及该模块的代码生成分支，因此并未造成这个模块二进制变化。

发现并修复两处增量打包残留：

1. sysdrv driver 构建成功后，替换 `output/out/sysdrv_out/kernel_drv_ko`，不再复制覆盖旧目录。
2. firmware 填充资源前替换 OEM `usr/ko`，使已裁掉 sensor 的旧 `.ko` 不会继续进入镜像。

不删除 source/staging 的其他库和用户文件；离线测试使用真实 SDK Makefile 片段及打包 shell 代码，
验证旧 sensor 模块消失、新模块保留，邻接 rootfs tar 和 librockit 不受影响。
候选 OEM 中 30 个 `.ko`，不含已关闭 sensor；ALSA/DRM 用户空间库仍保留供 Rockit 动态链接。

这轮补丁保存到已有五个 SDK patch target：kernel 第20条、sysdrv 第3条、project 第3条、BoardConfig 第10条。
重放发现旧 KMPP 第2/3条 patch 文件末尾缺少必要上下文行，已从**相同的既有提交**重新导出，
没有修改 KMPP 源码。patch 的上下文空行本身带空格，不要通过“删除所有行尾空格”破坏补丁；
patch 目录 attributes 排除该类格式空格检查，实际有效性由完整重放验证。

验证通过：Distrobox 的 5 项新回归测试、8 项 patch-stack 测试、全部63个锁定 SDK 项目检查、
五个 patch target 的隔离重放/重复 apply、runtime ELF/库检查、A/B 烧录 dry-run、脚本语法检查。
另外用 B 的 expected config 检查仍运行 A 的板子，脚本正确拒绝且没有启动摄像头。

## A：三次双路软件基线

每次每路120帧，每次 sender/viewer 正常退出；总720帧全部 VAAPI 硬解，零 malformed/duplicate/dropped，
完整 WaitFreeMB/SYS_Exit。USB 独立 `/dev/kmsg` 通道收到唯一 marker；marker 后无 BUG、WARNING、软/硬锁。
六次非交错的启动前/结束后温度快照范围44.64–46.46°C。没有 netconsole、绑核或临时频率设置。
结束后 boot_id 未变，SSH 在线，没有 sender 或监控进程遗留。

下面均为 ms，每路360个样本。mean 按样本数加权，P95 是**三个 run 的分位数范围**，不是合并后的P95。

| 软件区间 | camera0 mean / run P95范围 | camera1 mean / run P95范围 |

| 板端完整 AU 就绪→发送前 | 0.107 / 0.123–0.127 | 0.134 / 0.154–0.256 |

## 烧录 B 与后续 B→A 回测

当前 SDK `.BoardConfig.mk` 已选择 K1，`../aura-sdk/output/image` 是 B。
为防止后续构建覆盖，实际烧录指定独立镜像目录；A 副本为本轮构建前的原镜像。
烧录和物理重启都由用户操作。

```sh

./tools/flash-aura-emmc --images artifacts/kernel-ab/20261013/B/image
```
